# 31. MODEL C — STEP BY STEP

Suppose the input is one receipt.

```text
                   ORIGINAL IMAGE
                         │
              ┌──────────┴──────────┐
              │                     │
              ▼                     ▼
        VISUAL PATH            LAYOUT PATH
```

---

## PATH 1 — VISUAL

The original image is resized and passed through MobileNet.

```text
Original Image
      ↓
Resize 224×224
      ↓
MobileNetV3
      ↓
Visual Feature Vector
```

Instead of making the final Real/AI decision immediately, we take an internal representation such as:

```text
[0.82, -0.14, 0.57, 0.03, ...]
```

These numbers are the model's compact numerical representation of:

> **what the image visually looks like.**

This is called a:

> feature vector / embedding.

---

## PATH 2 — LAYOUT

The same original image is passed through OCR.

```text
Original Image
      ↓
OCR Text Detection
      ↓
Text Bounding Boxes
      ↓
Create Layout Map
      ↓
Tiny CNN
      ↓
Layout Feature Vector
```

Example layout feature vector:

```text
[0.31, 0.92, -0.45, 0.17, ...]
```

These numbers summarize:

> **how the text regions are spatially arranged.**

---

# 32. MODEL C — FEATURE FUSION

Now we have:

### Visual features

```text
[0.82, -0.14, 0.57, 0.03]
```

### Layout features

```text
[0.31, 0.92, -0.45]
```

The simplest fusion method is literally to concatenate them:

```text
[0.82, -0.14, 0.57, 0.03,
 0.31, 0.92, -0.45]
```

This combined vector is then passed through a small classifier:

```text
Combined Features
       ↓
Small MLP
       ↓
Real probability
AI probability
```

Example:

```text
REAL = 0.18
AI   = 0.82
```

Final prediction:

> AI-generated

# 35. WHY MODEL C MAY HELP EVEN THOUGH THE ORIGINAL IMAGE ALREADY CONTAINS THE LAYOUT

> yes, the visual CNN already sees the positions of the text because the positions exist in the pixels.

But the hypothesis is:

> a normal visual model must simultaneously learn textures, colors, objects, fonts, artifacts, backgrounds, semantic structure, and everything else.

The explicit OCR-layout branch removes all those distractions and tells another part of the system:

> **focus only on where the text is arranged.**
